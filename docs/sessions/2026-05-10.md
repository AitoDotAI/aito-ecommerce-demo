## Step 2 (commit `224e6ea`)
- ADR 0002 + `data/generate_fixtures.py` (~750 lines) emit
  658 / 3000 / 11970 / 37508 rows from seed=42, byte-identical
  across runs. `tests/test_fixtures.py` validates each engineered
  signal range.
- Tuning notes:
  - The Bought Together lift is `1 / P(dryfood-dog in any order)`
    once dental-treats appears *only* via the conditional boost.
    To hit ≥ 2.5× I had to drop dry-food's share of dog-leaning
    line picks to 13 % and bump the boost rate to 0.70.
  - Maija ∩ Olli top-5 wouldn't disjoin while Olli was sampling
    pet_type from `SEGMENT_PET_TYPE_WEIGHTS["multi_pet"]` (50/45
    dog/cat). Added a per-persona `pet_type_weights` override
    that lets Olli skew dog-heavy (85/15) without changing the
    `multi_pet` segment defaults for the wider population.
  - Naturally-null fields on accessories/toys/grooming bloated
    signal #4 the first run (53 % vs 4–6 % target). Restricted
    the Filling-pile pool to `FILLABLE_CATEGORIES` and re-fill
    any incidental nulls before the deliberate ones.

- Live Aito quirk recorded in the cheatsheet:
  `_search where { name: "food" }` returns 0 hits on a `Text`
  column. The right shape for token matching is
  `_search where { name: { "$match": "food" } }` (385 hits).
  Plain-string equality is whole-string equality, not tokenised
  match. Smart Search's customer-context reverse-link `$context`
  shape still needs work — first attempt returned 400; record
  the verified shape when the Smart Search view is built.
