  - **Link traversal in `_relate`**: `product_sku.category`

    (`order_lines.product_sku.category`,

## Step 6 — Smart Search (2026-05-11)
- ADR 0006 + `src/search_service.py` + `/api/smart-search`
  endpoint + frontend page. The headline demo moment is live.
- Adapted spec: TASK.md says "cat food drops from rank 1 to
  rank 6". The data has a dog-heavy catalog so baseline ranks
  Royal Canin **dog** food first. The actual moment is
  stronger: **same query string, totally different product list
  per persona**.
  - Maija (cat_owner) → 5/5 cat food at the top, all ★new
  - Saara (dog_owner+large) → 5/5 large-breed dog food
    (Acana/Hill's/Eukanuba — not Royal Canin), all ★new
  - Olli (multi_pet, small) → mixed cat + small_animal, also
    all ★new vs baseline
- **Schema migration**: added denormalised `customer_segment`
  and `customer_pet_size` columns to `order_lines`. Aito only
  does single-hop link traversal on `_recommend` from
  `order_lines`; two-hop
  `order_id.customer_id.segment` returned 400. Reset+reloaded
  the live DB (~50 s end-to-end).
- **Query shape locked + cheatsheet'd**: the right form is
  `_recommend product_sku from order_lines
   where {product_sku.name: {$match: q}}
   goal {customer_segment, customer_pet_size}`. With
  `goal: {returned: false}` the customer-context signal washes
  out (returned is uniform at ~3%). With `goal: {customer_segment}`
  the segment becomes the differentiator and the flip is dramatic.
- Per-customer (`order_id.customer_id: CUST-...`) conditioning
  is too thin for 3000-customer dataset to learn from. Segment
  (≈600 customers per group) is what produces the visible flip.
- The Aito panel now updates its `query` block with the *actual*
  body that ran on every search — including the live segment +
  pet_size in the goal.

  pill bar (Maija/Olli/Saara) flips the grid live, end-to-end

- **Aito quirk discovered + cheatsheet'd**: multi-field `goal`
  does NOT behave like an AND. `goal: {segment: "dog_owner",

## Step 8 — Bought Together (2026-05-11)
- ADR 0008 + `src/bought_together_service.py` +
  `/api/bought-together` endpoint + frontend at
  `/bought-together`. The headline 2.72× dog-dryfood →
  dental-treats lift now reads from a **live** `_relate`
  call, not from the Python pass.
- **Schema migration**: added `orders.line_categories` Text
  column. For each order, fixture-gen builds
  `space-separated <pet>_<category-no-hyphens>` tokens (e.g.
  `dog_dryfood dog_dentaltreats cat_wetfood`). Aito tokenises
  on whitespace — each underscored pair stays one feature.
  Hyphens are stripped because Aito ALSO tokenises on hyphens
  (`dry-food` → `dry` + `food` otherwise).
- **Live live query** (verified, recorded in the cheatsheet):

  ```json
  POST /api/v1/_relate
  {
    "from": "orders",
    "where": { "line_categories": { "$match": "dog_dryfood" } },
    "relate": "line_categories",
    "limit": 12
  }
  ```

  Returns `dog_dentaltreats` at lift = 2.72×, matching the
  Python reference in `tests/test_fixtures.py` exactly. Also:
  `dog_wetfood` 1.54×, `dog_treats` 1.53×, `cat_wetfood` 0.27×
  (anti-correlated).
- **Cross-sell threshold**: lift < 1.2 is filtered out. Patterns
  in the 0.5-1.2 band are "neither bought together nor
  protective" — noise for this view; they belong in Pattern
  Explorer. Aquarium → aquarium-health (8.4×, niche) appears
  as the single cross-sell when the user picks aquarium —
  honest: aquarium is a closed-ecosystem buyer.
- **Verified anchors live**:
  - `dog_dryfood`     → 4 cross-sells, lead `dog_dentaltreats` 2.72×
  - `cat_wetfood`     → 3 cross-sells (cat dry-food / treats / litter)
  - `cat_litter`      → 2 cross-sells (cat wet-food / cat dry-food)
  - `aquarium_aquarium` → 1 cross-sell (aquarium-health 8.37×)
- The same 2.72× number now reads in three independent surfaces:
  Dashboard tip-box (Python-computed), Dashboard top-patterns
  bar (Python-computed), Bought Together (live `_relate`).
  Cross-page numeric consistency without any framework code
  enforcing it.

  (`Sensitive`, `2kg`, `Dog`) as features.

### Evaluation
- Four `_evaluate` models run in parallel (~30 s cold, < 100 ms
  cached). Three pass with comfortable gain margins; **Return
  Risk fails with +0.0 pp gain** — the engineered honest-
  failure case from fixture signal #5.
- Aito quirk + cheatsheet update: `_evaluate` requires
  **`testSource` AND `evaluate`** (not just `evaluate`). My
  initial body shape (`{"evaluate": {...}}`) returned 400
  "either test or testSource must be defined". Now wraps as
  `{"testSource": {"from": …, "limit": 200}, "evaluate":
  {...}, "select": ["accuracy", "baseAccuracy", "n"]}`. Also
  bumped `httpx` timeout from 30 s → 90 s; the return-risk
  evaluate against `order_lines` (37 k rows × 200 test cases)
  routinely exceeds 30 s and we were silently swallowing it
  as zero-accuracy.
- Pet-type's `baseAccuracy = 0.0` is a known Aito quirk —
  consistent across runs; `accuracy_gain` is still the
  reliable pass/fail signal. Documented in ADR 0010.
