## Step 5 (2026-05-11)
- ADR 0005 + `src/overview_service.py` + Dashboard frontend.
  `/api/dashboard` reads live from Aito for KPI counts (658 /
  10 156 / 3 000 / €75 avg basket against the 12-month window)
  and segment shares (dog 42.1 % / cat 29.8 % / multi 15.2 % /
  small_animal 7.3 % / aquarium 5.6 %). Top patterns computed
  Python-side from the local fixtures because cross-row order-
  level co-occurrence needs a `_relate` shape we'll only pin
  with the Bought Together ADR (0008). Cached 10 min in the
  two-layer cache.
- Aito quirks discovered:
  - **`order_by={"$desc": "month"}`** is the right syntax for
    descending sort. Plain string `"-month"` returns 400 ("field
    '-month' not found"). Recorded in the cheatsheet.
  - **Link traversal in `_relate`**: `product_sku.category`
    works for *line-level* relations (within-row), but Aito
    doesn't expose a clean way to query "orders whose lines
    contain category X" without a reverse-link `_relate` shape
    I haven't pinned. First-attempt syntaxes
    (`order_lines.product_sku.category`,
    `{"$context": {…}}`) all returned 400. Bought Together's
    ADR is where the live shape lands; Dashboard's summary uses
    the Python computation as the fall-back.
  - **(pet_type, category) granularity for lift**: conditioning
    on bare `category="dry-food"` (which includes cat dry-food)
    diluted the dog→dental lift from 2.68× to 1.45×. The
    engineered moment is specifically *dog* dry-food → *dog*
    dental-treats. Pattern keys widened to
    `((pet, cat_a), (pet, cat_b))`.
  - **Insight tip-box pick**: with strict sort-by-lift, aquarium
    → aquarium-health (16.8×, niche-driven) bumps the dog→dental
    moment off the headline. The dashboard now preserves the
    curated `_PATTERN_PAIRS` order and the insight builder
    explicitly anchors on "Dog dry-food → Dental treats". A
    narrative beats raw ranking in the load-bearing tip-box.

## Step 6 — Smart Search (2026-05-11)
- ADR 0006 + `src/search_service.py` + `/api/smart-search`
  endpoint + frontend page. The headline demo moment is live.
- Adapted spec: TASK.md says "cat food drops from rank 1 to
  rank 6". The data has a dog-heavy catalog so baseline ranks
  Royal Canin **dog** food first. The actual moment is
  stronger: **same query string, totally different product list
  per persona**.
  - Maija (cat_owner) → 5/5 cat food at the top, all ★new
  - Saara (dog_owner+large) → 5/5 large-breed dog food
    (Acana/Hill's/Eukanuba — not Royal Canin), all ★new
  - Olli (multi_pet, small) → mixed cat + small_animal, also
    all ★new vs baseline
- **Schema migration**: added denormalised `customer_segment`
  and `customer_pet_size` columns to `order_lines`. Aito only
  does single-hop link traversal on `_recommend` from
  `order_lines`; two-hop
  `order_id.customer_id.segment` returned 400. Reset+reloaded
  the live DB (~50 s end-to-end).
- **Query shape locked + cheatsheet'd**: the right form is
  `_recommend product_sku from order_lines
   where {product_sku.name: {$match: q}}
   goal {customer_segment, customer_pet_size}`. With
  `goal: {returned: false}` the customer-context signal washes
  out (returned is uniform at ~3%). With `goal: {customer_segment}`
  the segment becomes the differentiator and the flip is dramatic.
- Per-customer (`order_id.customer_id: CUST-...`) conditioning
  is too thin for 3000-customer dataset to learn from. Segment
  (≈600 customers per group) is what produces the visible flip.
- The Aito panel now updates its `query` block with the *actual*
  body that ran on every search — including the live segment +
  pet_size in the goal.

## Step 7 — For You (2026-05-11)
- ADR 0007 + `src/recommend_service.py` + `/api/for-you`
  endpoint + tile grid frontend at `/recommendations`. Persona
  pill bar (Maija/Olli/Saara) flips the grid live, end-to-end
  in well under 300 ms.
- **Aito quirk discovered + cheatsheet'd**: multi-field `goal`
  does NOT behave like an AND. `goal: {segment: "dog_owner",
  pet_size: "small"}` returned the same cat-heavy result as
  `goal: {pet_size: "small"}` alone, because `pet_size=small` is
  shared between small dog_owners and small multi_pet households
  (which lean cat in our fixture). The reliable shape is to
  **split**: pet_size in `where`, segment in `goal`. Verified live;
  the same fix applied retroactively to Smart Search (where Saara
  worked by accident — `pet_size=large` is mostly dog_owner so the
  combined goal happened to land on the right segment).
- **Olli persona override**: the customer record says
  `multi_pet+small` but the Aito goal uses
  `dog_owner+small` — matches his hand-curated 85 %-dog
  history. UI label stays "multi-pet, small dog" per TASK.md;
  the panel shows the live goal body. Documented as a
  "demo-time goal override" pattern in ADR 0007.
