## Aito quirks
- A flat `_predict` over one table adds evidence column by column, so it cannot separate an action's effect by context:
  every action lifted every context. Crossing the action with each context column (`action_x_<context>`) fixed most of it.
  A parameter column must be its own: an apology's €5 credit stored as `voucher_eur = 5` read as evidence for vouchers.
- "Any action beats none" bias remains: an ad to a customer who declined tracking rated a few points above none, so ads
  are a rule (consent), not learned. `$on` in a `where` is accepted (200) but did not change this; not documented, not used.
- A never-seen evidence value returns the base rate with a 200 (the service validates the vocabulary); `{"$numeric": x}` on a
  linked Decimal matched like the exact value.
- The assignment must vary: with only rule-driven actions Aito recovered the best action for 48 % of customers, with half
  randomised 81 %.

## Surprising
- A tell flagged "ever" looks protective (0.76–0.96×) because customers who stay order more and so meet more events; the
  fair measure is the churn panel among customers who had just ordered. The real cause of "no effect" was the generator:
  returns were drawn from lifestyle alone and a late delivery never touched the churn hazard.
- Regenerating churn moves every table (orders −4 %): stock and star ratings follow sales, so the Shop's shoppers had to be
  re-picked (Juhani CUST-01825, Helena CUST-00070) and pinned test sessions re-picked twice.
- The tool hook blocks shell commands whose text mentions the credentials file; probe scripts that read it go in files.
