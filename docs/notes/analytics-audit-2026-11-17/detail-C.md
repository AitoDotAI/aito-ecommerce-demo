Repo: /home/arau/episto/src/aito-ecommerce-demo. Read-only audit, no network.

Routing facts
- `/churn` and `/demand` are redirect stubs (frontend/app/churn/page.tsx:1-6, frontend/app/demand/page.tsx:1-6; frontend/lib/moved-routes.ts:28) to Retention and Supply (ADR 0041). Churn is now the Retention page; demand is now Supply. `/api/demand` (src/app.py:767-773) has no frontend consumer. Its content is the demand snapshot (forecast top movers, season `_relate` lifts, `_evaluate`). Churn accuracy (`src/churn_evaluation.py`) and demand accuracy (`src/demand_evaluation.py`) show only in Evidence > Model checks (src/evidence/model_checks.py:27-37).
- Retention and Supply are served from stored snapshots: data/precomputed/v2-master/{retention,supply,demand}.json (frontend page -> /api/retention|supply -> `_precomputed_view`, src/app.py:751-764).
- Writer: `./do precompute [--as env] [--files-only] [--only supply,overview]` (do:429-468) -> `precompute_all` (src/precompute.py:52-113) -> `get_retention` / `get_supply` / `get_demand`. These **query a live Aito host** (_predict, _relate, _estimate, _search) and then do Python arithmetic. They do not compute from fixtures. Fixtures (data/*.json, written by data/generate_fixtures.py) are only the data loaded INTO Aito.
- Origin (c) means the number is an input table value a page shows verbatim, such as stock, reorder point or unit cost. No page number is a hand-typed constant, except thresholds and cost parameters (listed below).
- The aito-core docs say what Aito can do. Cites: SQL = aito-core/docs/sql-support.md; QR = aito-core/api-docs/content/query-reference-v2.md; EV = evaluation-v2.md; CS = docs/aito-cheatsheet.md.
- The demo never calls `_sql`. `AitoClient` has `aggregate()` (src/aito_client.py:516-551) and `search()`, so `_aggregate` is available but unused by these views.
- All numbers on both pages are read in Python by `read_all` (src/catalogue_reads.py:15-24), which pages `_search`.
