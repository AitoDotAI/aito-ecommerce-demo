# TASK.md — Predictive E-commerce

The working brief for this project. The ADRs in `docs/adr/` cite it
section-by-section; the file is the **source of intent** for the
demo's eight views and five demo moments. The framework-level
conventions live in [`aito-demo-framework.md`](aito-demo-framework.md);
this document is the e-commerce-specific brief on top.

---

## 1. What this demo is

A working pet-store front (PetNord — a Nordic-flavoured online pet
shop) wired against an Aito predictive database. The point is to
show what an e-commerce platform looks like when **predictions are
native** to every screen — search results, recommendations, cross-
sell, catalog enrichment, evaluation — without a separate model
training pipeline.

Family-line brand: **Predictive E-commerce** ·  matches the sibling
demos `aito-accounting-demo` (*Predictive Ledger*) and
`aito-erp-demo` (*Predictive ERP*). The product-of-aito.ai line is
shipped consistently across the three demos.

PetNord is the dataset / persona — `PetNord · Nordic pet store` —
shown as a chip at the top of the sidebar, one level below the
family brand.

## 3. Stack (constraints)

Per the cross-demo framework:

- **Backend** — Python 3.12, FastAPI, single-file `app.py`, one
  service module per view, two-layer cache (in-memory LRU +
  Aito-backed `prediction_cache` table).
- **Frontend** — Next.js 16 (App Router) + TypeScript.
- **Ports** — port pair `8500` (Next.js) ⟷ `8501` (FastAPI).
- **Aito panel** — locked structure / colours per
  `aito-demo-framework.md §5.3`. Each view sets its
  `AitoPanelConfig` (endpoints, query body, links) via
  `usePagePanel(...)`.
- **Single tenant** — no multi-tenant routing. The dataset
  *is* PetNord.

## 4. Data model

Four tables (single-tenant). Counts are the demo target — enough
volume that `_relate` produces visibly different lift scores
across segments (~0.5×–3.5×), small enough for the Aito free tier.

```
products      ~700 rows
customers   ~3 000 rows
orders     ~14 000 rows over 24 months (2024-05 .. 2026-04)
order_lines ~36 000 rows  (avg 2.6 lines per order)
```

Generated by `data/generate_fixtures.py` with engineered demo
signal so the five demo moments produce stable, quotable numbers
on every reload.

## 5. The ten views

```
Overview        →  Dashboard          (KPIs, top patterns, segments, recent orders)
Assist          →  Smart Search       (predictive re-ranking)
                →  For You            (personalised tile grid + persona switcher)
                →  Bought Together    (cross-sell with lift scores)
Analyze         →  Purchase Analytics (month bars, top products, AOV by segment)
                →  Pattern Explorer   (ad-hoc _relate query builder)
Understand      →  Feedback           (multi-field _predict over review text)
                →  Churn              (P(churn) per customer + drivers + accuracy)
Automate        →  Product Filling    (multi-field _predict for catalog enrichment)
                →  Evaluation         (pass/fail rows; honest failures allowed)
```

Each view in this list gets:
- `frontend/app/<route>/page.tsx` — Server Component, fetches its
  data + sets its `AitoPanelConfig` for the panel.
- A panel-content builder keyed by route in
  `frontend/lib/panel-content.ts`.
- A service module on the backend; an ADR in `docs/adr/`; tests
  in `tests/` doubling as usage examples.

Sidebar order is the order above; that's also the order they ship
in the build plan below.

### Dashboard blocks

Four blocks (mock lines 564–719):

1. **KPI grid** — products, orders (12 mo), customers, avg basket.
2. **Top purchase patterns** — co-purchase lift bars per
   `(pet_type, category) → category` pattern (e.g. dog dry-food
   → dental treats ≈ 3.1×).
3. **Customer segments** — emoji + share + avg basket +
   descriptor per segment (dog / cat / small animal / aquarium).
4. **Insight + Recent orders** — a one-line discovery and a 6-row
   recent-orders table.

## 6. The five demo moments

These are the load-bearing predictions. The demo's credibility
rests on Aito producing visible, quotable results for each one:

### Moment #1 — Smart Search rank flip

> Side-by-side standard vs. predictive results for the query "food"
> with a large-breed dog-owner context. **Cat food drops from rank 1
> to rank 6** because the customer has never bought cat products.
>
> _This is the strongest visible-aha moment in the demo. Do not
> weaken it._

### Moment #2 — For You persona switch

> Personalised tile grid for a selected customer, with a
> customer-switcher pill bar to flip context live (Maija / Olli /
> Saara). Aito panel shows `_recommend` with `goal` (probability
> of purchase) and `where` (customer profile). Switching from
> Maija (cat owner) to Olli (multi-pet, small dog) flips the
> entire recommendation grid in <300 ms.

### Moment #3 — Bought Together lift

> Anchor product + four cross-sell tiles with lift scores. Aito
> panel shows the `_relate` query and how lift is computed.
>
> Dog dry-food → dental treats lift 3.1×; the panel shows the
> `_relate` query and the lift math.

### Moment #4 — Product Filling

> Incomplete product card on the left (missing category, weight,
> tax_class, dietary, …); on the right, the same five fields
> filled in by Aito with confidence chips. Aito panel shows
> multi-field `_predict` for catalog enrichment.

### Moment #5 — Evaluation (honest failures allowed)

> Pass/fail rows for each prediction model (recommendations,
> smart search, product filling, return risk) with accuracy
> bands and last-evaluated timestamps. Aito panel shows the
> `_evaluate` endpoint and the evaluation methodology.
>
> If one model honestly fails its threshold, **show it failing**
> — the demo is more credible with one red row than four green
> ones.

## 7. Build order

The demo ships one view per commit, in this order, with a feature
branch / ADR / verification cycle per step (see `CLAUDE.md`
§Feature workflow). Each step is mergeable on its own; main is
demo-runnable at every step.

3. Aito client + two-layer cache wiring; schema upload + load-data

5. Dashboard
6. Smart Search
7. For You
8. Bought Together
9. Purchase Analytics
10. Pattern Explorer
11. Product Filling
12. Evaluation
13. Live Aito mode (no fallbacks; every view talks to Aito; the
    sanity-check pass `./do aito-check` lights green)

## 8. Aito feature surface

The demo exercises six Aito endpoints visibly:

- `_search` — Smart Search (token match for the "standard" column)
- `_match` — Smart Search (predictive column; required for `Text`
  fields)
- `_recommend` — For You (personalised grid)
- `_relate` — Bought Together, Pattern Explorer, Dashboard top
  patterns
- `_predict` — Product Filling (multi-field), Smart Search
  re-ranking, Evaluation accuracy
- `_evaluate` — Evaluation view

The panel for each view names the endpoint, shows the live query
body, and links to the Aito docs page for that endpoint.

## 9. Out of scope

This demo deliberately does **not** ship:

- **Multi-tenant routing.** The dataset is PetNord; there is no
  `?tenant=` parameter and no tenant chip in the topbar.
- **Per-customer (`customer_id`) recommendation personalisation.**
  Segment / persona conditioning is sufficient for the visible
  moments; per-customer adds latency without changing the demo
  story on a 3 000-customer dataset.
- **Bulk catalog enrichment.** Product Filling is per-product;
  bulk fill belongs in a separate Catalog Operations story.
- **Date-range picker** on Purchase Analytics. Fixed-window is
  enough for the demo.
- **Auth / sessions.** This is a public reference demo with no
  PII; everything is anonymous.

## 10. Acceptance

The demo is "done" when:

- All eight views are wired live (no mocked data; every number on
  every screen comes from Aito).
- All five demo moments produce their headline numbers on a clean
  data load.
- `./do check` passes (tests + `aito-check` + format).
- `./do demo` works on a fresh clone in under five minutes.
- The README's quick-start works as written for an outside
  developer with `git`, Python 3.12, and Node 20 on PATH.
